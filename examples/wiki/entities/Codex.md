# Codex

[[entities/OpenAI]]'s coding agent, available both as a local CLI and as a cloud service. In the sources captured here, Codex is the **sole author** of an internal OpenAI product built end-to-end as an "agent-generated codebase" experiment.

## Known facts (from this knowledge base)

- The initial scaffold of the experimental repo was generated by **Codex CLI using GPT‑5**, guided by a small set of existing templates
- Even the initial `AGENTS.md` that directs agents how to work in the repo was written by Codex itself
- Single Codex runs frequently work on one task for **>6 hours** (often overnight)
- Codex uses standard developer tools directly (`gh`, local scripts, repository-embedded skills) rather than relying on humans to copy-paste into a CLI
- Codex can drive the application through the Chrome DevTools Protocol — DOM snapshots, screenshots, navigation
- Codex can query a local observability stack with LogQL (logs) and PromQL (metrics)
- In the right harness, Codex can drive a feature end-to-end: reproduce bug → record video → fix → validate → record resolution video → open PR → respond to feedback → merge

## Throughput data point (single OpenAI team, ~5 months)

- ~1,000,000 lines of code
- ~1,500 pull requests merged
- 3.5 PRs/engineer/day with 3 engineers; throughput continued to rise as the team grew to 7
- Manually-written lines: **0**
- Roughly **1/10th** the time it would have taken to write by hand

## Constraints on using Codex effectively (from Lopopolo's account)

1. The repo should be a "map + structured `docs/`", not a giant AGENTS.md encyclopedia
2. Architecture must be strictly layered (`Types → Config → Repo → Service → Runtime → UI`), enforced by custom linters
3. Prefer **boring technology** (API-stable, composable, well-represented in training data) over the trendiest libraries
4. Encode taste as **lint rules**, not as prose advice in docs
5. **Garbage-collect entropy continuously** with background Codex tasks doing small refactors, rather than letting tech debt compound
